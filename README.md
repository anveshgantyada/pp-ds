## Scoring Model: Percentile-Normalized Hybrid Readiness Model

Because no ground-truth outcome labels exist (no historical BDR conversion data),
this model uses **percentile normalization** rather than supervised ML.

Each signal is transformed into a relative standing within the CRM population —
identifying records that are unusually engaged, unusually good-fit, or attached
to unusually high-intent accounts.

### Components

| Component | Weight | Method | What it measures |
|-----------|--------|--------|-----------------|
| Engagement | 50% | Percentile rank **within entity type** | Recency, 30d responses, 90d responses, webinar/event attendance — penalized by automation share |
| Account Fit | 20% | Percentile rank cross-population | ICP match, named account, target industry, employee count, revenue |
| Persona Fit | 15% | Calibrated ordinal map | Job persona + seniority level |
| Intent | 15% | Account intent score percentile | Is this account high-intent vs the rest of the database? |

### Formula
```
readiness_score = 100 × (
    engagement_component × 0.50 +
    account_component    × 0.20 +
    persona_component    × 0.15 +
    intent_component     × 0.15
)
```

### Key Design Choices

**Entity-type calibration:** Engagement percentiles are computed separately for
leads and contacts. This prevents contacts (richer data) from systematically
outranking leads (thinner data).

**Automation discount:** `engagement_component × (1 - 0.5 × auto_share)` — records
where 70%+ of interactions are automated email sends are penalized directly.

**Missing account = 0.25, not 0:** Orphan leads with no account linkage receive
a neutral mid-low account score rather than zero, avoiding unfair punishment.

**Quantile-based tiers:** Tiers are assigned based on the score distribution of
actionable records — not arbitrary fixed thresholds.

### Priority Tiers

| Tier | Population | Action |
|------|------------|--------|
| 🟢 Call Now | Top 10% | Call immediately |
| 🟡 Work This Week | Next 20% | Call this week |
| 🔵 Nurture | Next 40% | Keep warm |
| ⚪ Low Priority | Bottom 30% | Deprioritize |
| 🔴 Blocked | Hard blocked | Do not contact |

### Why Not ML?
- No labeled conversion data → can't train supervised model honestly
- Logistic regression / XGBoost would require simulated labels, undermining validity
- Percentile ranking is statistically sound, fully explainable, and auditable

## Data Quality Issues Covered

| Issue | How handled |
|-------|-------------|
| DQ-1: Broken conversion links | `BROKEN_CONV_LINK` flag |
| DQ-2: Email duplication | Email type classification |
| DQ-3: MQL date overwrites | Ignored — uses campaign response dates |
| DQ-4: ETL-dominated timestamps | Ignored — uses campaign response dates |
| DQ-5: Score field asymmetry | Normalized separately by entity type |
| DQ-6: Non-prospect contamination | Hard blocked via flags |
| DQ-7: Data completeness gaps | Score reduced + `INCOMPLETE_PROFILE` flag |
| DQ-8: Automation-inflated engagement | Direct multiplier penalty on engagement |
| DQ-9: Opted-out / bounced records | Flagged; excluded unless recent event attendance |
| DQ-10: DQ field resets | `STALE_LEGACY_SCORE` flag as substitute signal |
| DQ-11: Free email domain leakage | Extended domain blocklist |
| DQ-12: Stale curated views | Bypassed — pipeline reads raw tables directly |
